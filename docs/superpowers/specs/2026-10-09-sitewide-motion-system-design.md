# 全站页面动效系统设计

## 目标

为观象建立统一、克制、方向明确的页面过渡系统，减少首页、登录页、主应用和信息页之间的僵硬闪切，同时不牺牲操作速度、可访问性或旧浏览器兼容性。

动效采用已经确认的方案 B：优先使用浏览器原生 View Transition API，不支持时使用 CSS 降级。普通页面切换控制在 `240–320ms`；首页进入登录页保留已经实现的 `1.1s` 仪式性离场动画。

本次不重构为单页应用，不改变 URL、账户、占卜、记录或存储模型，也不以动画掩盖网络等待。

## 设计原则

1. **层级决定方向**：同级栏目淡入淡出；列表进入详情向前推进；返回列表反向退出。
2. **响应优先**：普通切换不超过 `320ms`，菜单和弹窗不超过 `220ms`，输入、搜索和起卦推进不增加人为等待。
3. **只动画合成属性**：主要使用 `opacity` 和 `transform`，不动画宽高、边距、定位或大面积阴影。
4. **一次只强调一个变化**：页面容器负责过渡，页面内部卡片不逐个飞入，避免杂乱和眩晕。
5. **功能独立于动画**：脚本、原生 API或动画失败时，导航仍立即完成。
6. **尊重系统偏好**：`prefers-reduced-motion: reduce` 下关闭所有非必要页面动效和人为等待。

## 动效语言

### 同级切换

用于主应用的首页、六十四卦、占问、记录、十翼和易理栏目之间切换。

- 旧内容：`160–200ms` 淡出并缩小到 `0.992`；
- 新内容：`240–280ms` 从下方 `8px` 回到原位并显现；
- 不使用左右滑动，因为一级栏目之间不存在稳定的前后层级；
- 侧栏、顶栏和手机导航保持稳定，只更新当前状态。

### 前进与返回

用于六十四卦列表进入卦象详情、记录列表进入记录详情，以及手机端主从视图。

- 前进：旧内容向左 `12px` 淡出，新内容从右 `16px` 进入；
- 返回：方向反转；
- 时长 `260–300ms`；
- 浏览器后退、页面内返回按钮和点击列表项使用一致方向。

### 跨文档跳转

用于首页、登录页、主应用入口和七个信息页之间跳转。

- 支持跨文档 View Transition 的浏览器使用原生过渡；
- 其他浏览器由共享模块先执行约 `180ms` 的轻微淡出，再导航；新页面加载后以 `220ms` 显现；
- 页面背景色在整个过程保持观象纸色，避免白屏闪烁；
- 首页进入登录页是例外，继续使用六爻收束和标题淡出的 `1.1s` 动画；
- 浏览器前进/后退从 BFCache 恢复时清理旧离场状态并播放轻微显现。

### 局部交互

- 对话框：背景遮罩 `180ms`，内容缩放 `0.98 → 1` 并淡入，最长 `220ms`；
- 语言菜单和手机“更多”菜单：`160–200ms` 淡入并移动 `4–6px`；
- 登录/注册模式切换：表单正文 `200ms` 交叉淡入，不清除输入和焦点；
- 不给搜索结果、文本输入、起卦每一步、滚动和数据加载增加页面级动画。

## 架构

### 共享过渡模块

新增 `page-transition.mjs`，提供两个明确入口：

- `navigateWithTransition(url, options)`：处理同域跨文档跳转；
- `runViewTransition(update, options)`：包装当前文档内的同步 DOM 更新。

模块自行判断：

- 是否开启减少动态效果；
- `document.startViewTransition` 是否存在；
- 当前是否已经处于过渡中；
- 导航是普通、前进还是返回；
- 是否需要使用 CSS 降级。

同一时间只允许一个页面过渡。快速连续点击时，以第一次有效导航为准；当前过渡完成前不重复启动动画。

### 跨文档链接

共享模块在 `index.html`、`auth.html` 和全部信息页初始化，并只拦截满足以下条件的链接：

- 普通左键点击；
- 同源 HTTP(S) 地址；
- 当前标签页导航；
- 非下载、非纯锚点、非外部链接。

带修饰键、新标签页、`target="_blank"`、下载链接、GitHub 等外链和浏览器默认行为不被拦截。JavaScript 直接跳转的位置，如登录成功、游客进入和退出登录，显式调用 `navigateWithTransition()`。

### 主应用内部路由

现有 `nav()`、`applyRoute()`、记录详情和手机卦象详情不改变 URL 规则。新增薄封装管理可见视图更新：

- 一级栏目调用 `runViewTransition(..., {kind:'peer'})`；
- 列表进入详情调用 `{kind:'forward'}`；
- 返回列表调用 `{kind:'back'}`；
- `popstate`/`hashchange` 根据旧路由和新路由判断方向；
- 初次加载不播放内部切换动画。

实际内容渲染仍由原函数负责，过渡模块不持有业务数据，也不读取占卜记录。

### CSS 状态

三类页面共用同一组语义状态，而不是各自创造动画名称：

- `data-transition="peer|forward|back"`；
- `.page-is-leaving`；
- `.page-is-entering`；
- `.transition-fallback`。

原生 View Transition 使用固定的 `view-transition-name` 对页面主体命名；侧栏、顶栏和固定导航不参与快照移动。CSS 降级只作用于同一个主体容器。

## 状态与焦点

- 过渡开始时暂时阻止重复的页面导航，但不禁用滚动之外的整个文档；
- 新视图渲染完成后再更新标题、面包屑和 `aria-current`；
- 过渡完成后按现有逻辑移动焦点，不能让焦点停留在已隐藏元素；
- 返回列表时优先恢复到原来打开详情的条目；
- 对话框打开后焦点仍进入对话框，关闭后返回触发按钮；
- 动画类在 `finish`、取消、异常和 `pageshow` 时都必须清理。

## 登录和网络操作

登录与注册请求期间只显示现有加载/禁用状态，不预先播放离场动画。只有服务器确认成功后才启动进入主应用的过渡。

请求失败时页面保持原位并显示错误，不能先淡出再弹回。游客进入不依赖网络，可以立即启动短过渡。退出登录完成本地状态清理后再跳转登录页。

## 错误与兼容

- `document.startViewTransition` 不存在时使用 CSS 降级；
- CSS 动画不支持或执行失败时直接更新 DOM/导航；
- 回调抛错时清理过渡状态并把错误交回现有错误处理；
- 页面在过渡中被浏览器挂起或恢复时，通过 `pageshow` 重置状态；
- JavaScript 未加载时所有普通链接仍然可用；
- `prefers-reduced-motion: reduce` 下不添加离场延迟，DOM 更新和导航立即发生；
- 动画不得改变页面可点击区域、布局尺寸或滚动高度。

## 测试与验收

### 单元与静态测试

1. 原生 API 可用时调用 `startViewTransition`；
2. 原生 API 不可用时完成 CSS 降级并清理状态；
3. 减少动态效果时立即执行更新和导航；
4. 重复导航不会启动两个过渡；
5. 外链、新标签、下载和纯锚点不被拦截；
6. 构建产物和 Service Worker 包含共享模块。

### 浏览器测试

1. 首页到登录页完整播放现有 `1.1s` 离场动画；
2. 登录成功和游客进入不会闪现未授权的主页面；
3. 主应用一级栏目在 `320px`、`390px` 和桌面视口平滑切换且无布局跳动；
4. 记录列表进入详情是前进方向，返回是反向；
5. 六十四卦手机列表与详情方向一致；
6. 信息页互相跳转时不出现白屏，当前页状态正确；
7. 浏览器前进/后退后页面可交互、焦点合理、无残留过渡类；
8. 模拟不支持 View Transition 时 CSS 降级可用；
9. 减少动态效果模式下没有人为延迟；
10. 现有首页、账户、占卜、历史记录、三语和响应式测试全部继续通过。
