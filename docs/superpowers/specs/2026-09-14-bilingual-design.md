# 观象中英双语设计

## 目标

为观象周易研读应用增加中文/English 双语界面。除经典原文外，所有面向用户的页面文字、按钮、提示、筮法步骤、易理说明、本地解读和 AI 解读均可随语言切换。中文为默认语言，用户选择持久化到浏览器。

## 内容边界

- 保持中文原文：`ten-wings.json`、`hexagram-texts.json` 中的卦辞、爻辞、彖传、象传及十翼引文。
- 可翻译内容：导航、页面标题、字段标签、占筮引导和动画状态、错误提示、历史/札记界面、卦名说明、易理专题、规则解读、AI 解读。
- 卦名和八卦名在英文界面显示英文转写并保留中文识别，例如 `Qian (乾)`；原文区增加明确的中文底本标记。
- 用户输入的问题、札记和导入的历史内容视为用户数据，保持原样，不自动翻译。

## 语言架构

新增轻量语言模块（建议 `i18n.mjs`），提供：

- `LANGUAGES`、`getLanguage()`、`setLanguage()` 和 `t(key, params)`；语言只允许 `zh-CN`、`en`。
- 集中式界面词条表，词条使用稳定 key，缺失英文词条时回退中文并记录开发期警告。
- `data-i18n`、`data-i18n-aria-label`、`data-i18n-placeholder` 属性用于静态 HTML；动态模板通过 `t()` 生成。
- `document.documentElement.lang`、页面标题、导航面包屑和所有 aria/placeholder 随切换更新。
- 语言选择器放在顶栏，使用可访问的 segmented control；选择保存至 `localStorage`，刷新和 hash 深链接后恢复，不重置占筮状态。

说明型 JSON 数据保留中文字段作为底本，同时增加对应的英文展示字段（例如 `title_en`、`overview_en`、`concepts_en`）。经典原文 JSON 不增加译文，渲染层只对说明字段选择语言。

## 动态解读协议

`buildLocalInterpretation(context, { language })` 根据语言选择分类词条、阶段描述、行动建议和警示；输出结构保持现有字段不变，便于离线工作。英文解读不得翻译或改写经典原文，只翻译解释性句子。

AI 请求 payload 增加 `language: "zh-CN" | "en"`。Worker 校验该字段并按语言选择 system prompt 和五段标题；英文标题使用稳定 ID 映射，不依赖中文标题解析。客户端 `splitAiReadingSections(text, language)` 同时解析中英文标题，错误消息也从词条表取值。AI 缓存键必须包含语言，防止中英文结果串用；旧版无语言字段的缓存按中文处理并可自然失效。

## 页面覆盖

覆盖 landing cover、总览、六十四卦列表/详情、完整大衍筮法和快速模式入口、结果阅读、十翼索引与古籍排版控制、易理专题、占问记录、导入导出、首次使用、重置确认、AI 状态和离线提示。原文阅读模式（古籍次序/现代纵读）只翻译控件，不改变篇次和原文顺序。

## 错误与兼容

- 不支持的语言值回退 `zh-CN`。
- 翻译缺失回退中文，同时在开发环境输出一次警告，不阻塞页面。
- Worker 收到非法语言返回现有 `INVALID_REQUEST`；网络、限流、模型不可用等错误按当前语言显示。
- service worker shell 版本递增并包含新增模块，确保离线可用。
- 不修改现有经典数据和用户历史格式；历史记录读取时缺少语言字段视为中文记录。

## 测试标准

- 单元测试：语言选择/持久化、词条回退、动态模板关键页面、中文/英文本地解读、AI 中英文标题解析和语言隔离缓存键、Worker payload 校验。
- 内容检查：静态 HTML 与 JS 中面向用户的中文字符串清单，允许原文数据、用户输入和开发日志，发现未登记文案时失败。
- 浏览器冒烟：切换语言后检查六个视图、占筮推进、结果阅读、十翼原文、历史导入导出和移动端布局；刷新后语言保持。

## 分阶段交付

1. 语言基础设施、静态页面和导航/控件。
2. 六十四卦、十翼、易理说明的双语展示与本地解读。
3. 大衍筮法动态步骤、结果页、历史/札记和 AI Worker 端到端双语。
4. 漏译扫描、离线缓存更新、单元与浏览器回归测试。
