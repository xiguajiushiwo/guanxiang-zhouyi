# 信息与支持页面设计

## 目标

为观象补齐正式产品需要的信息入口和独立页面框架，包括支持中心、更新日志、专业版、免责声明、隐私、反馈留言和举报，并在支持区域展示小红书、抖音、X 与 GitHub。

本次只建立页面、导航和视觉框架，不编写正式正文，不接入付费、会员权限、反馈提交、举报邮件或后台存储。GitHub 使用项目真实地址；小红书、抖音和 X 在没有真实主页地址前显示“即将开放”，不可跳转。

实现继续放在 `codex/liuyao-complete` 分支，不修改 `main`，不自动发布 Cloudflare。

## 页面与网址

新增七个独立静态页面，并支持省略 `.html` 的直达网址：

| 页面 | 源文件 | 公开路径 |
| --- | --- | --- |
| 支持中心 | `support.html` | `/support` |
| 更新日志 | `changelog.html` | `/changelog` |
| 专业版 | `pro.html` | `/pro` |
| 免责声明 | `disclaimer.html` | `/disclaimer` |
| 隐私 | `privacy.html` | `/privacy` |
| 反馈留言 | `feedback.html` | `/feedback` |
| 举报 | `report.html` | `/report` |

每个页面都是可独立刷新、收藏和分享的真实页面，不依赖登录状态，也不进入现有单页应用路由。Cloudflare Pages、当前 Node 本地服务器和构建后的静态目录都必须能正确打开这些路径。

## 页面内容边界

七个页面只包含以下框架内容：

- 观象品牌与返回首页入口；
- 当前页面名称和对应英文副标题；
- “即将开放”的状态说明；
- 七个信息页面之间的导航；
- 统一的社交入口；
- 版权信息。

不从参考网站复制任何正文、联系方式、备案号、账户权益、法律文本或作者社交账号。免责声明和隐私页面在正式正文完成前不得展示容易被误解为完整法律条款的摘要；只明确标注页面尚在准备中。

## 共享页面壳

新增共享的 `info.css` 和 `info.js`。各 HTML 页面只声明自己的页面标识，其余标题、导航状态、语言文本和社交状态由共享模块管理，避免七份页面逻辑分叉。

页面视觉延续现有观象风格：纸张底色、墨色文字、朱砂强调色、细线结构和克制的卦象圆形背景。页面主体保持简洁，但不能只在空白页面中放一行字：使用一个稳定的标题区、状态区和信息导航区形成完整构图。桌面端为左右平衡布局，手机端改为单列，不出现横向滚动或文字重叠。

页面顶部包含：

- 观象标记与品牌名；
- 返回首页；
- 中文、English、فارسی 语言选择。

页面主体包含：

- 页面中文标题；
- 对应英文识别文字；
- 简短的“即将开放”状态；
- 返回支持中心或浏览其他信息页面的入口。

页面底部包含七个信息页面链接、GitHub 外链及三个未开放社交状态。

## 现有页面入口

不把九个入口全部挤进现有封面首屏。现有页面只增加一个清晰的“支持与关于”入口，进入支持中心后再展示完整信息导航。

- 首页封面：在底部区域增加“支持与关于”，手机端仍可见，不改变“进入观象”的主按钮层级；
- 登录页：在底部增加“支持中心”入口；
- 应用桌面端：在侧栏底部增加“支持中心”入口；
- 应用手机端：在“更多”菜单中增加“支持中心”入口。

所有入口使用普通链接，因此即使应用脚本加载失败仍能打开支持页面。信息页面返回首页时进入封面，不绕过现有登录流程。

## 社交入口

社交区域使用以下固定行为：

- GitHub：真实外链 `https://github.com/xiguajiushiwo/guanxiang-zhouyi`，在新标签页打开，并使用安全的 `rel` 属性；
- 小红书：禁用状态，显示“即将开放”；
- 抖音：禁用状态，显示“即将开放”；
- X：禁用状态，显示“即将开放”。

未开放项使用不可点击的状态元素，不使用空链接、`#`、虚假主页或参考网站作者的账号。后续拿到真实地址后只需修改共享配置，不改七个页面结构。

## 语言

信息页面跟随现有本地语言设置，支持中文、英文和波斯文。首次打开使用现有语言偏好，切换后写回同一语言键，并同步：

- 页面标题；
- “即将开放”状态；
- 页面导航名称；
- 返回首页和支持中心；
- 社交平台状态；
- 浏览器标题与 `lang`、`dir`。

波斯文页面使用 RTL，但品牌名、GitHub、X 等专有名称保持正确方向。页面没有正式正文，因此不引入不完整的长篇翻译。

## 可访问性与交互

- 当前信息页面在导航中使用 `aria-current="page"`；
- 禁用社交项不可获得键盘焦点，并以可读文字说明“即将开放”；
- GitHub 外链有清楚的辅助说明；
- 语言菜单可以键盘操作并用 Escape 关闭；
- 触摸目标不小于 44 像素；
- 在减少动态效果模式下关闭装饰动画；
- 页面不依赖 JavaScript 才能看到标题、状态和基础导航，JavaScript 只负责语言和当前状态增强。

## 构建、缓存与路由

`build-pages.mjs` 将七个 HTML 页面、`info.css` 和 `info.js` 复制到 `dist`。Service Worker 更新缓存版本并缓存这些静态文件；导航离线回退根据请求路径返回对应信息页，不能把 `/privacy` 或 `/support` 错误回退成应用首页。

Node 本地服务器现有的无扩展名 HTML 解析继续用于 `/support` 等路径。Cloudflare Pages 使用同名 HTML 文件提供无扩展名页面；若部署环境未自动支持无扩展名路径，则增加静态重写配置，而不是使用应用首页兜底冒充成功。

## 错误与兼容

- JavaScript 未加载时，各信息页仍显示中文标题、即将开放状态和链接；
- 本地存储不可用时，语言选择只在当前页面生效；
- 离线时，已缓存的信息页仍可访问；
- 未开放社交入口永远不触发导航或提交；
- 新页面不读取账户、占卜记录或问题内容，不影响原有本机记录和云端同步；
- 现有首页、登录页、应用路由和手机底部导航保持原有行为。

## 测试与验收

新增静态和浏览器测试覆盖：

1. 七个源页面和构建产物均存在；
2. `/support` 等无扩展名路径在本地生产服务器返回对应页面；
3. 七个页面互相可达，当前页面标识正确；
4. 首页、登录页、桌面侧栏和手机“更多”菜单都能进入支持中心；
5. GitHub 指向项目真实地址并安全地在新标签页打开；
6. 小红书、抖音和 X 显示“即将开放”且不可点击；
7. 中文、英文、波斯文切换和 RTL 正确；
8. 320px、390px 和桌面视口无横向滚动、遮挡或文字重叠；
9. 禁用 JavaScript时仍能读取页面标题和基础导航；
10. Service Worker 缓存清单与离线导航回退包含全部信息页面；
11. 现有单元测试、账户测试、首页浏览器测试和完整占卜流程继续通过；
12. `npm run build:pages` 生成可部署的完整静态目录。

验收完成后提交并推送 `codex/liuyao-complete`，等待用户审阅本地页面，再单独决定是否发布 Cloudflare。
