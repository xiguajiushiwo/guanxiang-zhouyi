# Complete Liuyao Dual-Mode System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a complete, locally reproducible Liuyao Najia chart alongside the existing Jing-zhuan reading flow, with editable casting time, compatible history records, and desktop/mobile result views.

**Architecture:** Keep the existing yarrow casting engine as the source of six line values. Add pure modules for sexagenary calendar conversion and Liuyao rules, then generate a serializable chart at cast completion. The result UI exposes two independent tabs, while storage and cloud sync treat the Liuyao chart as an optional field so old records remain valid.

**Tech Stack:** Browser-native ES modules, Node.js unit tests, existing static HTML/CSS, `lunar-javascript@1.7.7` vendored for solar-term and Gan-Zhi conversion.

**Spec:** `docs/superpowers/specs/2026-09-22-liuyao-complete-design.md`

## Global Constraints

- Preserve the existing `main` branch and online deployment; all work happens on `codex/liuyao-complete`.
- Preserve existing six-line order: index `0` is 初爻 and index `5` is 上爻.
- Keep the classic reading path usable when calendar data or Liuyao calculation is unavailable.
- Store user-entered cast time as the authoritative time; never silently replace it with view time.
- Do not label later Liuyao rules as original Zhouyi text.
- Run `npm test` and `npm run test:browser` before pushing the branch.
