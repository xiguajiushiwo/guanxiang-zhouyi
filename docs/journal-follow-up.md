# 占问记录：跟进与复盘

记录详情现在包含判断与行动计划、复盘日期、可追加的进展时间线，以及四问复盘。保存复盘后进入“已复盘”，也可以“继续跟进”；列表的“待复盘”按照设备当地日期计算，包括当天和已过期且尚未完成的记录。提醒在站内显示，不发送系统通知。

新占问首次保存本地解读时会留存快照。AI 重新生成会追加版本，并保留首次留存的结果。旧记录只有此前最后保存的 AI 内容可以迁移，不能恢复以前已被覆盖的版本；没有本地快照的旧记录明确显示“依据当前资料生成的解读”。

复盘使用独立的 `journal` 字段，与经典批注的 `reviewState` 分开。进展与复盘条目具有独立 ID、类型和时间，多设备合并保留双方追加的条目；计划字段采用较新的记录。`aiReadings` 保存历史版本，`aiReading` 保留兼容的最新版本字段；本地快照采用最早留存的一份。旧记录、札记及导入导出格式保持兼容。

本地记录及云端列表取消了静默截取前 100 条的行为。单条记录的界面最多追加 100 次进展/复盘、生成 10 版 AI 解读，达到上限会提示导出归档，不覆盖已有内容。浏览器存储空间耗尽时显示保存失败，保留正在填写的内容。账户请求体上限提升至 4 MiB，以容纳版本及时间线。

详情页直接链接和刷新可进入记录；账户初始化完成之前保留目标记录 ID。经典 JSON 分别读取，整段请求（含 JSON 响应体读取）具有 10 秒超时；失败显示重试，已存解读与复盘仍然可用。资料加载完成和后台同步不会清除当前表单草稿。未提交草稿不跨页面刷新保存。

## 验证

- `npm run test:unit`：包含数据迁移、版本留存、日期判断、超过 100 条记录、多设备合并、账户 API 和加载超时。
- `npm run test:journal`：浏览器验证加载失败及重试、详情刷新、320/390px 手机与桌面布局、计划/进展/复盘保存、筛选、AI 失败及重新生成、延迟账户加载与云端同步。
- `npm run test:browser`、`npm run test:flow`：原有主流程回归。
- `npm run build:pages`：打包新增模块与样式，离线缓存同步升级到 v51。

## 发布

本次涉及前端静态站点、账户代理与 `account-worker`。先更新账户 Worker，再部署前端/代理，使云端使用追加式合并规则与新的请求上限。无需 D1 表结构迁移，新增字段存放在已有 `payload_json` 中。本地构建和测试不会自动部署线上站点。
